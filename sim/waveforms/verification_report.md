# Integrated cache verification evidence

## Testbench and commands

The verification extends the existing `sim/testbenches/tb_cache_top.v` and
instantiates the real `cache_top`, cache controller, cache storage, address
decoder, performance monitor, and main-memory model. Memory is seeded with the
deterministic pattern `0x600d0000 + word_index` after the memory model's initial
zeroing and before synchronous reset is released.

Run the full Issue #7 and Issue #8 suite and generate all isolated VCD runs from
the repository root:

```sh
bash sim/run_cache_top_verification.sh
```

The runner compiles with `iverilog -g2012 -Wall` and executes with `vvp`. Its
source dependencies are `rtl/address_decoder.v`, `rtl/cache_storage.v`,
`rtl/cache_controller.v`, `rtl/performance_monitor.v`,
`memory/main_memory_model.v`, `rtl/cache_top.v`, and
`sim/testbenches/tb_cache_top.v`. The compiled image is placed in
`${TMPDIR:-/tmp}/mca-cache-issue8/`.

## Waveform contents and limitations

The VCDs are generated by actual isolated `vvp` runs. They include clock/reset,
CPU request/write/address/data and response signals, controller state,
performance counters, memory request/response/address/block data, cache refill
and word-write controls, plus selected cache valid/tag/data and main-memory
word values. The runner checks that each file is non-empty, has VCD definitions,
and that important signals are present with multiple recorded samples.

## Existing unit-test regression

The existing unit benches were compiled with `iverilog -g2012 -Wall` and run
from a temporary output directory so their legacy VCD names did not overwrite
the repository's existing waveforms.

| Existing testbench | Actual result | Status |
|---|---|---|
| `tb_address_decoder` | 374 checks, 0 errors | PASS |
| `tb_cache_storage` | All cache storage tests passed | PASS |
| `tb_cache_controller` | All tests passed; 13 accesses, 7 hits, 6 misses | PASS |
| `tb_main_memory` | Block read, word write, readback, and 5-cycle latency passed | PASS |
| `tb_memory_init` | Memory-file contents matched expected block data | PASS (Icarus emitted the expected sparse-file warning described below) |
| `tb_performance_monitor` | All 10 monitor tests passed | PASS |

The testbench uses hierarchical references to the existing storage and memory
arrays to verify line contents and write visibility. It is therefore coupled to
the current RTL instance names. No RTL changes were needed. Byte and unaligned
accesses are outside this prototype's documented aligned-word contract. The
existing `tb_memory_init` intentionally supplies only four initialization
words; Icarus reports that the file has fewer words than the 4096-word memory
range, then the test confirms the addressed initialized block. No other compile
warnings or simulation errors were observed.
